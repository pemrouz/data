watch one path propagate

A live blotter, ticking. Each update mutates exactly one path — trades[i].field = value — and only the affected cell flashes. Sibling fields are never visited; work is proportional to the path that changed, not the row.

why incremental?

Work is proportional to the path that changed — not the row, not the dataset, not anything broader. When you mutate a deeply-nested property: 

trades[1234].bid = 99.85

…the underlying notification carries the exact path ['1234', 'bid'] and the new value. Each layer in the pipeline does work scoped only to that path: filter reruns its predicate for one row, between does a single bisect step, intersect flips one bitmask entry per source, za repositions one entry in its sorted index, and the DOM updates the single binding tied to the changed path. No diff pass, no list re-render, no key reconciliation.

A typical Redux + virtual-DOM stack re-runs the entire selector chain over all 5,000 trades on every tick. With one tick per millisecond, that doesn't scale at all. Operators here are written for minimum-work propagation by construction.

operators

Every operator below is a view derived from the same trades proxy backing the blotter above. Streaming bid/ask/pnl mutations propagate through each chain incrementally — no recomputation outside the changed path. Click a tab to switch; the stream keeps running across all of them.

filter — pick a tenor

Rows matching a predicate. Click a chip to switch.


      

      

    


    

      
between — brush by pnl

      
Rows where a column falls in a range. Each dot is one
        trade at its current pnl; the orange band is the active range.

      

      

      

        
        
      

    


    

      
za / az — top / bottom by pnl

      
Sort descending (za) or ascending
        (az), optionally limited. Top 5 winners and
        bottom 5 losers, re-ranking live as pnl ticks.

      
trades.za('pnl', 5)
trades.az('pnl', 5)

      

      

    


    

      
length — count, total or grouped

      
Total row count, or counts under a key.

      
trades.length()
trades.length(d => d.tenor)

      

    


    

      
sum / avg / max / min / some / every — scalar aggregates

      
Each returns one number (or boolean) derived from every
        row, updated incrementally — sum / avg are O(1) per delta, max / min
        are O(n) per publish, some / every flip when their counter crosses.

      
trades.sum('pnl')             // total exposure
trades.avg('pnl')             // mean
trades.max('pnl'), trades.min('pnl')
trades.some(t => t.pnl > 1000)
trades.every(t => t.pnl > 0)

      

    


    

      
intersect — filter ∩ filter

      
Rows present in every source view. Profitable trades at
        the chosen tenor.

      

      

      

    


    

      
union / except — set algebra companions

      
Same bitmask machinery as intersect:
        union keeps rows in any source,
        except keeps rows in the source but not
        the other.

      

      

      

    


    

      
group — nest by tenor

      
Rows nested under a computed key. Each tenor becomes its
        own bucket, with its trades indented underneath.

      
trades.group(d => d.tenor)

      

    


    

      
distinct / keys / values / reverse — collection projections

      
Reactive views over the shape of the data:
        distinct dedups rows by a projection,
        keys/values
        unzip an object-shaped view, reverse
        flips order.

      
trades.distinct(t => t.tenor)
trades.length(t => t.tenor).keys()
trades.length(t => t.tenor).values()
trades.za('pnl', 5).reverse()

      

    


    

      
map — derive bid-ask spread

      
Per-row transform. The new spread
        column is computed from each row's bid & ask; it updates whenever
        either field ticks.

      
trades.map(d => ({ ...d, spread: d.ask - d.bid }))

      

    


    

      
to / reduce — aggregate pnl

      
to rebuilds a derived value
        from the whole snapshot on every tick.
        reduce folds row-by-row through
        (acc, row, key) => acc — a more
        readable shape for the same kind of aggregation, especially with
        non-commutative folds (string concat, object merge).

      
trades.to(arr => arr.reduce((s, t) => s + t.pnl, 0))
trades.reduce((s, t) => s + t.pnl, 0)

      

    


    

      
tap — side effects in a chain

      
Passthrough that fires fn(change)
        for every event flowing through it AND propagates the same event
        downstream. Below: tap'd into the live top-5 so you see the
        per-tick rank-change events as they happen.

      
trades.za('pnl', 5).tap(change => log.unshift(change))

rendering

    

      Two surfaces over the same NodeProxy AST. The builder DSL composes nodes
      directly; the JSX adapter compiles to the same calls. render()
      walks an identical tree either way, and DOMSink does per-key surgical
      updates — element identity and focus survive across reactive changes.
    


    
builder dsl


import { $, render, HTML } from 'data'
const { ul, li } = HTML

const todos = $([{ task: 'foo' }, { task: 'bar' }])

render(document.body,
  ul(todos, (node, item) => node.text(item.task))
)

todos.insert({ task: 'baz' })   // a new <li>baz</li> appears



    
jsx


/** @jsx h */
import { $, render, h, For } from 'data/full'

const todos = $([{ task: 'foo' }, { task: 'bar' }])

render(document.body,
  <ul>
    <For each={todos} tag="li">
      {(item) => <li>{item.task}</li>}
    </For>
  </ul>
)

todos.insert({ task: 'baz' })   // a new <li>baz</li> appears
