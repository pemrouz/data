comparisons

How data lines up against crossfilter, MobX, RxJS, React, and the modern signal libraries (Solid, Preact, Vue, Svelte).

This page isn't a "we win" page. The reactive landscape is wide; each library optimises for a different shape. The aim here is to make the shape differences visible — model, mutation API, where work actually happens — and then back the discussion with reproducible numbers from a single workload run across every library.

Two live comparison pages run the same workload across nine libraries in your browser: multidim for interaction-driven filtering (brushable charts over 231k rows), and trades for row-update-driven streaming (a live order book over 10k limit orders with a drifting regime). Per-row latency / CPU-cost trackers expose where each library spends time.

per-operator benchmarks

Rolled up across every peer measured in npm run bench:ops. Each operator runs on 10,000 rows; single is one row mutation then read, batch streams 1,000 such ticks back-to-back. Multiplier is peer_time / data_time — values > 1× mean the peer is slower than data by that factor. Values < 1× (rare, flagged in the operator's own table) mean the peer is faster — at the sub-µs scale where measurement noise and signal-equality short-circuits in peer libs dominate. row-update-driven

trades — live order book

A streaming tick replaces one of 10,000 limit orders' bid or ask per emission. Each row maintains four reactive views — bid- and ask-bucket depths, liquid count, avg bid — rendered as a cumulative depth chart + price ladder. A drifting regime (mid, spread bias, imbalance on three incommensurate sine waves) keeps the shape evolving. data's O(1)-per-tick length(fn) + aggregate cascade against peers' O(N) walks per get.

where data isn't the right tool

  • You need a full UI framework. Solid and Svelte ship with everything (router, transitions, server-side rendering); data's render layer is intentionally minimal.
  • You're composing async event streams. RxJS is the right tool — debounce/throttle/combineLatest/switchMap exist for a reason. data stays in the synchronous, point-update lane.
  • You want a static dimensional analytics index over a fixed dataset. Crossfilter's groupAll().reduceSum/Count over precomputed dimensions wins on raw query throughput when the data doesn't change.
  • You're already inside a Vue/React/Svelte/Solid component tree. Use the framework's reactivity — adding data on top adds a second graph for no gain. data is most useful when you don't have a framework's reactivity already.
