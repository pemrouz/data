streaming ticks — live

A synthetic market-data tape, rebuilt once per reactive library, all reading the same stream.

Each row receives identical batches of {symbol, sector, price, volume, pctChg, time} ticks and maintains the same six views using its own reactive primitives: top 3 / bottom 3 by % change (per-symbol LWW state, ~200 keys), sector volume, a 10-bin % change distribution, and two scalars (total volume, avg %change) — all over a rolling window of the last — ticks. The window is pre-filled at startup so peer libs walk a full N from the first timed batch (otherwise the gap stays hidden for the ~100 s it takes the window to fill at 5k ticks/s). The strip on the right is the wall-clock cost of each library's ingest(batch) + render rollup, p50 / p95 over the last 100 batches — directly comparable across rows because it's just the lib's reactive layer doing its work. Drag the rate slider to push the libs harder; the ones doing O(n) rebuilds per tick fall behind first, until very high rates where data's per-tick reactive overhead overtakes them in turn.
