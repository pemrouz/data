See your graph

devtools/ ships an inspector panel and a DOM overlay. The panel is a right-edge dock: the live graph as a Tree or a DAG, every commit's deltas as they settle, and the settle time of each node. It mounts on demand — never on its own — and the console API alone ($.inspect, $.graph, $.trace, $.profile, $.cascades) doesn't pay the panel's bytes. The overlay walks the other way: $.fromDOM($0) picks any bound element back to the view that rendered it; $.highlight(view) lights up its rows.

not mounted · this page runs a five-node graph

Everything the panel shows is a projection of two runtime primitives — runtime().graph() and runtime().onCommit(c => …) — so the numbers are the kernel's own, measured only while a hook is live.

See your graph

devtools/ ships an inspector panel and a DOM overlay. The panel is a right-edge dock — this is it, drawn inline over a five-node graph this section runs on the page's engine, with a scripted writer feeding it real writes. devtools/index.ts alone — the graph, trace and profile helpers this page imports — never loads the panel; the data/devtools entry also docks it on import unless the URL says ?nopanel, and devtools/panel/ mounts only through mountPanel().

  • Tree / DAGthe live graph — id · kind · op · height · parents, from runtime().graph()
  • Eventsone line per commit: the write, the cascade in settle order, deltas per node
  • settle msper-node timing from onCommit — measured only while a hook is live
  • $.fromDOM($0)the overlay: any bound element → the view that rendered it; $.highlight(view) lights its rows

Console-only: $.inspect(h) · $.graph() · $.trace(fn) · $.profile(fn) · $.cascades(fn). $.trace subscribes for the duration of fn and disposes after — tracing has zero steady-state cost.

lazy — devtools/panel/ loads on click

$.devtools.panel.open() / .close() drive it from the console in any page that imports data/devtools — $.inspect(h) alone stays in the console.
