what is real · The strip runs the engine on the page: `trades = $({ t1…t5 })` (five object-born rows, one of them a sell), `buys = trades.filter(t => t.side === 'buy')`, `largest = buys.za('qty', 2)`, `volume = buys.sum('qty')`. "run it ▸" issues `trades.t3.qty.update(v)` with v alternating 500 ↔ 380 (a same-value write is a kernel no-op — the `Object.is` cut-off in `SourceNode.write` — so it must alternate; the WRITE card prints the call actually issued). The rest state is a real boot-time write (500 → 380), so first paint shows a landed commit and no attested element is ever empty. The old smoke (BEFORE/AFTER tables, the fake seq counter, the random 0.03–0.07 ms, the "3 nodes / 1 text node" string) is deleted, not hidden. There is no timer, loop or writer in this section other than the button: nothing runs while the section is hidden or off-screen.

runtime (engine-produced, `data-attested="runtime"`) · WRITE: `trades.rowCount()`, `trades.t3[value]` (sym · side), `trades.t3.qty[value]` (read back after the write). DELTA: the RowDelta `trades.sink({ apply })` delivered — op / key / path / prev / row printed as the algebra spells them (`prev` and `row` are the whole pre-/post-write rows, elided to the written leaf: `{ …, qty: 500 }`), plus `batch.seq` and `batch.rows.length`. VIEWS: buys from `buys.sink()` — "re-tested · stays" only if the commit's CommitInfo shows 0 deltas for buys' node id, otherwise what filter emitted (here `update t3 · stays in`: the update passes through the predicate); largest from `largest.sink({ wantsOrder: true, init, apply })` — a WINDOWED za emits the survivor's `orderMove` (`t2` 1 → 0), so t3's rank before → after is derived by replaying the order channel (orderRemove → orderInsert → orderMove, in array order) onto a local rank mirror seeded from `init`'s order (the scratch checks assert the mirror equals `currentOrder()` at every step); volume from `volume.connect(anchor, fn)` v2 records (`sink()` throws on scalars by design) — prev → next is the previous record's value → the current one; the per-node line (`filter 1 · za 2 · sum 1 deltas`) is the CommitInfo's `nodes[].deltas` (rows + order + scalar) in settle order. STATUS: `seq`, `origin` (the token's description — the kernel's default is `Symbol('user')`), `nodes.length` from `runtime().onCommit`'s CommitInfo; the hook is registered around the write and disposed after it, so other sections' commits stay unmeasured (page-wide there are 0 live hooks at rest). The chip accents are derived too: a chip is `is-hot` only when the engine says its view MOVED (buys: an add/remove in filter's batch, i.e. membership changed; largest: rank before ≠ after; volume: prev ≠ next) — the classes are no longer typed in the HTML.

measured (in this tab, `data-attested="measured"`) · the DOM card: `render(host, text(trades.t3.qty))` mounts the engine's own text node in `#arg-cell-b` (the digits there are the engine's node; the host is stamped runtime); a MutationObserver (`childList + characterData + subtree`) on the host is read with `takeRecords()` right after each write → `1 text · 0 added · 0 removed` (an independent MutationObserver attached by the review script reports the same counts). The status line's ms is ONE `performance.now()` interval around the write call — commit (4 settles) + effects (the sinks and the DOM text write) — labelled "write → dom in … ms · this machine". It is printed at the tab's clock resolution, which is itself measured at boot (a spin until `performance.now()` changes): Chromium clamps `performance.now()` to 100 µs unless the page is cross-origin isolated (Firefox: 1 ms), so the figure carries one decimal here (`0.4`, `2.2`), and an interval below one tick prints as `< 0.1` — never a decimal the clock cannot back. The element's `title` states the resolution. The rest-state figure is the cold first commit (JIT-cold kernel paths: 1.2–5.9 ms across runs); a click reads 0.1–0.5 ms.
