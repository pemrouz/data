the original sin of reactive UI

Only do the work that changed.

Almost every reactive system re-runs the whole computation when a single value changes. data is a reactive data engine that moves only the change: $() wraps a value, operators derive incrementally-maintained views, sinks deliver consolidated deltas, render binds to the DOM. Work scales with the change, not the dataset.

Like crossfilter's incremental aggregation meets Solid-style fine-grained DOM — for UIs over large, fast-changing data: dashboards, analytics, grids, live feeds.

change & derivation

A table and its change-stream are one thing.

A write is a delta — three row verbs, add · update · remove, in one batch envelope — and every operator consumes and emits exactly that. So a filter, a count, a grouping stays live for the price of the change, not the table. data keeps the table and its stream as one thing: wrap a value in $(), chain operators, bind to the DOM.

Like crossfilter's incremental aggregation meets Solid-style fine-grained DOM — for UIs over large, fast-changing data: dashboards, analytics, grids, live feeds.
