From zero

one package, nothing bundled — dist/ is the source type-stripped file-for-file, one module per file. In the repo it stays source-served: Node runs the .ts with --experimental-strip-types; this page runs the same files, type-stripped the same way.

api/the public surface — $(), the verbs, the operators, batch, runtime. The one entry you import.
seam/the outside-world boundary — ingest, lane, wireSink, mount
render/ + jsx/el / list / text, the HTML / SVG builders, classic + automatic JSX
devtools/the inspector panel + DOM overlay — mounts on demand, never auto

a source and its views

import { $ } from 'data'

const trades = $({
  t1: { sym: 'AAPL', side: 'buy',  qty: 200, px: 187.5 },
  t2: { sym: 'MSFT', side: 'sell', qty: 120, px: 412.1 },
  t3: { sym: 'NVDA', side: 'buy',  qty: 500, px: 118.4 },
})
const buys    = trades.filter(t => t.side === 'buy')
const largest = buys.za('qty', 2)
const volume  = buys.sum('qty')

trades.t3.qty.update(380)   // → update t3 .qty 500 → 380

bound to the DOM

import { render, el, list, batch } from 'data'

const ol = document.querySelector('ol')

render(ol, list(largest, t =>
  el('li', null, el('b', null, t.sym), t.qty)))

batch(() => {
  trades.t3.qty.update(380)
  trades.t1.qty.update(260)
})   // one commit, one paint

JSX works too (jsxImportSource: "data" — classic h or the automatic runtime). render() does per-key surgical updates — element identity and focus survive across changes.
