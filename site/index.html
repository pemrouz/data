the original sin of reactive UI

Only do the work that changed.

Almost every reactive system re-runs the whole computation when a single value changes. data is a reactive data engine that moves only the change: $() wraps a value, operators derive incrementally-maintained views, sinks deliver consolidated deltas, render binds to the DOM. Work scales with the change, not the dataset.

Like crossfilter's incremental aggregation meets Solid-style fine-grained DOM — for UIs over large, fast-changing data: dashboards, analytics, grids, live feeds.

change & derivation

A table and its change-stream are one thing.

A write is a delta — three row verbs, add · update · remove, in one batch envelope — and every operator consumes and emits exactly that. So a filter, a count, a grouping stays live for the price of the change, not the table. data keeps the table and its stream as one thing: wrap a value in $(), chain operators, bind to the DOM.

Like crossfilter's incremental aggregation meets Solid-style fine-grained DOM — for UIs over large, fast-changing data: dashboards, analytics, grids, live feeds.

      01
      The argument
      
      
      
        A change is small. You set one field on one row. Yet most reactive stacks
        respond by re-running everything downstream — re-filtering the whole list,
        re-summing every number, diffing an entire tree — and then trusting a
        memoiser to paper over the waste.
      
      
      
      
        data takes the change literally. A write carries its exact path,
        and each operator in the chain does work scoped to that path alone:
      
      
      
      trades.t3.qty.update(380)   // one delta · path ['qty'] · prev 500
      
      
        
        
      • filter re-tests the predicate for one row
        • 
        
      • za moves one rank
        • 
        
      • sum nudges a running total in O(1)
        • 
        
      • render rewrites only the single bound cell
        • 
      
      
      
      
        No diff pass. No list re-render. No selector re-run over 231,083 rows. The
        cost of an update is the length of the path it travels — which is why the
        race above holds at any rate, and why it scales to datasets that make
        recompute-everything systems stall.

          09Coalescingopt-in coalesce('microtask' | 'frame') — sugar, not semantics
          

          const q = () => [[{ n: 1 }], [{ n: 2 }]], commits = { sync: 0, co: 0 }  // two chunks that settle in one tick

while (sync.status() === 'pending' || co.status() === 'pending') await new Promise(r => setTimeout(r))
